# bsp-hpm5301evklite

HPM5301EVKLite 的 LibXR / XRobot BSP / LibXR and XRobot BSP for the HPM5301EVKLite

## 1. 板子与平台 / Board and Platform

开发板为 HPMicro HPM5301EVKLite（HPM5301，RISC-V，板载 1 MB QSPI NOR Flash），无操作系统，外设由 LibXR 的 `hpm` 驱动提供。工程是标准的 HPM SDK 应用：SDK 位于仓库之外，由环境变量 `HPM_SDK_BASE` 指定；板级文件 `boards/hpm5301evklite/` 基于 HPM SDK v1.13.0（`board.c`、`board.h` 在 SDK 板文件的基础上去掉了本板用不到的例程辅助函数），并按 HPM 自定义板的要求加入 SDK 中该板的 OpenOCD 配置 `hpm5301evklite.cfg`；`CMakeLists.txt` 通过 `BOARD_SEARCH_PATH` 使用它。时钟由 `clock.c`、引脚由 `pinmux.c` 设置，两者由 HPM Pinmux Tool（[tools.hpmicro.com](https://tools.hpmicro.com/) 或 VS Code 扩展）根据 `tool_config.hpmpc` 生成；BSP 使用的引脚集中在工具中新建的函数 `init_bsp_pins()` 中，每个引脚只分配给一个外设。`User/main.cpp` 调用 `init_bsp_pins()` 和各外设的时钟函数，`User/app_main.cpp` 创建 LibXR 对象并用 `XR_REGISTER` 完成硬件注册。配置中的硬件名即这些注册名：`LED`、`KEY`、`pwm_gptmr0_ch1`、`i2c3`。

```text
CMakeLists.txt            HPM SDK 应用工程
CMakePresets.json         构建预设
app.yaml                  HPM SDK 应用描述
boards/hpm5301evklite/    板级文件（HPM SDK v1.13.0）
cmake/LibXR.CMake         LibXR 接入与编译选项
Modules/modules.yaml      使用的模块（`xrobot:` 记录 XRobot 版本）
Modules/sources.yaml      源
xrobot.lock               每个模块使用的提交（lock）
User/main.cpp             板级初始化与外设引脚、时钟初始化
User/app_main.cpp         入口源文件，硬件注册并调用 XROBOT_MAIN()
User/xrobot.yaml          配置
libxr/                    LibXR 子模块
```

`Modules/<owner>/<Repo>/`、`Modules/CMakeLists.txt` 和 `User/xrobot_main.hpp` 由 `xrobot` 生成，已列入 `.gitignore`。

The board is the HPMicro HPM5301EVKLite (HPM5301, RISC-V, 1 MB on-board QSPI NOR flash), without an operating system; the peripherals are provided by the LibXR `hpm` driver. The project is a standard HPM SDK application: the SDK lives outside the repository and is named by the environment variable `HPM_SDK_BASE`, and the board files `boards/hpm5301evklite/` are based on HPM SDK v1.13.0 (`board.c` and `board.h` with the example helper functions that this BSP does not use removed), with the board's OpenOCD configuration `hpm5301evklite.cfg` from the SDK added as HPM requires for a custom board, and used by `CMakeLists.txt` through `BOARD_SEARCH_PATH`. Clocks are set by `clock.c` and pins by `pinmux.c`, both generated by the HPM Pinmux Tool ([tools.hpmicro.com](https://tools.hpmicro.com/) or the VS Code extension) from `tool_config.hpmpc`; the pins of the BSP are collected in `init_bsp_pins()`, a function created in the tool, with each pin assigned to one peripheral. `User/main.cpp` calls `init_bsp_pins()` and the clock functions of the peripherals, and `User/app_main.cpp` creates the LibXR objects and performs the hardware registration with `XR_REGISTER`. The hardware names used in a configuration are these registered names: `LED`, `KEY`, `pwm_gptmr0_ch1` and `i2c3`.

`Modules/<owner>/<Repo>/`, `Modules/CMakeLists.txt` and `User/xrobot_main.hpp` are generated by `xrobot` and listed in `.gitignore`.

## 2. 外设 / Peripherals

引脚为 `init_bsp_pins()` 中的分配。LibXR 尚无驱动的外设只完成引脚和时钟初始化。

| 外设 | 引脚 | LibXR 对象 |
| --- | --- | --- |
| LED | PA10，低电平点亮 | `HPMGPIO LED` |
| 按键 KEY&BOOT | PA03，按下为高电平 | `HPMGPIO KEY`，中断输入 |
| GPTMR0 通道 1 | PB08 | `HPMPWM pwm_gptmr0_ch1` |
| I2C3 | PB13 SCL、PB12 SDA | `HPMI2C i2c3` |
| UART0（控制台） | PA00 TX、PA01 RX | 由 `board_init()` 初始化 |
| UART3 | PB15 TX、PB14 RX | 引脚与时钟 |
| SPI1 | PA26 CS、PA27 SCLK、PA28 MISO、PA29 MOSI | 引脚与时钟 |
| ADC16 | PB10（ADC0.2） | 引脚与时钟 |
| ACMP | PB09 输出、PB11 输入 | 引脚与时钟 |
| USB0 | PA24、PA25、PY00、PY01 | 引脚与时钟 |

修改引脚时，在 HPM Pinmux Tool 中导入 `boards/hpm5301evklite/tool_config.hpmpc`，编辑 `init_bsp_pins`，再导出 `pinmux.c`、`pinmux.h` 和工程文件替换板目录中的同名文件。

The pins are those of `init_bsp_pins()`. Peripherals without a LibXR driver yet only have their pins and clocks initialized. To change pins, import `boards/hpm5301evklite/tool_config.hpmpc` into the HPM Pinmux Tool, edit `init_bsp_pins`, and export `pinmux.c`, `pinmux.h` and the project file over the files of the same name in the board directory.

| Peripheral | Pins | LibXR object |
| --- | --- | --- |
| LED | PA10, active low | `HPMGPIO LED` |
| Key KEY&BOOT | PA03, high when pressed | `HPMGPIO KEY`, interrupt input |
| GPTMR0 channel 1 | PB08 | `HPMPWM pwm_gptmr0_ch1` |
| I2C3 | PB13 SCL, PB12 SDA | `HPMI2C i2c3` |
| UART0 (console) | PA00 TX, PA01 RX | set up by `board_init()` |
| UART3 | PB15 TX, PB14 RX | pins and clock |
| SPI1 | PA26 CS, PA27 SCLK, PA28 MISO, PA29 MOSI | pins and clock |
| ADC16 | PB10 (ADC0.2) | pins and clock |
| ACMP | PB09 output, PB11 input | pins and clock |
| USB0 | PA24, PA25, PY00, PY01 | pins and clock |

## 4. 构建 / Build

构建需要 HPM SDK v1.13.0、CMake（3.23 或更高）、Ninja 和 HPM RISC-V GCC 工具链。环境变量 `HPM_SDK_BASE` 指向 SDK，`GNURISCV_TOOLCHAIN_PATH` 指向工具链目录。XRobot 为 1.0.0，与 `Modules/modules.yaml` 的 `xrobot:` 一致。

```bash
git clone --recursive https://github.com/xrobot-org/bsp-hpm5301evklite.git
git clone --depth 1 --branch v1.13.0 https://github.com/hpmicro/hpm_sdk.git
export HPM_SDK_BASE="$PWD/hpm_sdk"
export GNURISCV_TOOLCHAIN_PATH=<工具链目录>
cd bsp-hpm5301evklite
pip install xrobot==1.0.0
xrobot setup
cmake --preset debug-flash-xip
cmake --build --preset debug-flash-xip
```

镜像 `ghcr.io/xrobot-org/docker-image-hpm:main` 提供 CMake、Ninja、Python、工具链和 HPM SDK v1.13.0，并已设置 `HPM_SDK_BASE` 和 `GNURISCV_TOOLCHAIN_PATH`：

```bash
docker run --rm -v "$PWD:/src" -w /src ghcr.io/xrobot-org/docker-image-hpm:main \
  bash -c 'pip install xrobot==1.0.0 && xrobot setup && cmake --preset debug-flash-xip && cmake --build --preset debug-flash-xip'
```

`xrobot setup` 拉取模块、检查配置并生成 `User/xrobot_main.hpp`。预设如下，构建目录均为 `build/`，产物为 `build/output/demo.elf` 和 `build/output/demo.bin`。

| 预设 | `CMAKE_BUILD_TYPE` | `HPM_BUILD_TYPE` |
| --- | --- | --- |
| `debug-flash-xip` | Debug | `flash_xip` |
| `debug-ram` | Debug | `ram` |
| `release-flash-xip` | Release | `flash_xip` |

`cmake/LibXR.CMake` 为 C++ 代码加上 `-fno-exceptions -fno-rtti -fno-threadsafe-statics` 和 `-D_GLIBCXX_NO_ASSERTIONS`；HPM SDK 不设置这些选项。Debug 构建中应用代码为 `-O0`，LibXR 为 `-Os`，`debug-ram` 预设的全部代码运行在 128 KB 的 ILM 中。

`.github/workflows/build.yml` 在上述镜像中检查配置格式、按 `xrobot.lock` 解析模块，并以 HPM SDK v1.13.0 构建三个预设。其中的 `libxr-master` 作业每天运行一次，把 `libxr/` 更新到 LibXR 的 `master` 后构建，作业失败不影响工作流结果。

Building needs HPM SDK v1.13.0, CMake (3.23 or newer), Ninja and the HPM RISC-V GCC toolchain. The environment variable `HPM_SDK_BASE` points at the SDK and `GNURISCV_TOOLCHAIN_PATH` at the toolchain directory. XRobot is 1.0.0, matching `xrobot:` in `Modules/modules.yaml`. The image `ghcr.io/xrobot-org/docker-image-hpm:main` provides CMake, Ninja, Python, the toolchain and HPM SDK v1.13.0, with `HPM_SDK_BASE` and `GNURISCV_TOOLCHAIN_PATH` set, as in the commands above.

`xrobot setup` fetches the Modules, checks the configurations and generates `User/xrobot_main.hpp`. The presets are listed above; all of them build in `build/` and produce `build/output/demo.elf` and `build/output/demo.bin`.

`cmake/LibXR.CMake` adds `-fno-exceptions -fno-rtti -fno-threadsafe-statics` and `-D_GLIBCXX_NO_ASSERTIONS` to the C++ code; the HPM SDK does not set these options. In Debug builds the application code is built with `-O0` and LibXR with `-Os`; with the `debug-ram` preset all code runs from the 128 KB ILM.

`.github/workflows/build.yml` checks the configuration format, resolves the Modules from `xrobot.lock` and builds the three presets with HPM SDK v1.13.0 in the image above. Its `libxr-master` job runs daily, updates `libxr/` to the LibXR `master` branch and builds; a failure of that job does not fail the workflow.

## 5. 烧录与运行 / Flash and Run

`flash_xip` 预设的固件从板载 QSPI NOR Flash 执行，`ram` 预设的固件加载到 RAM 运行。KEY&BOOT 键同时是启动模式键，复位时按住它进入 ISP 模式，正常运行时不按。开发板的 JTAG 接口可用 J-Link 下载：

```bash
JLinkExe -Device HPM5301xEGx -If JTAG -JTAGConf -1,-1 -Speed 4000 -AutoConnect 1
```

在 J-Link Commander 中执行 `loadfile build/output/demo.elf`、`r`、`g`。OpenOCD 使用 SDK `boards/openocd/` 中的芯片和探针配置与板目录中的 `hpm5301evklite.cfg`，用法见这些配置文件的头部。运行后 LED 按 250 ms 周期闪烁。

With the `flash_xip` presets the firmware executes from the on-board QSPI NOR flash, and with the `ram` preset it is loaded into RAM. The KEY&BOOT key is also the boot mode key: holding it during reset enters ISP mode, and it is released for normal operation. The JTAG connector of the board works with J-Link, as in the command above; in J-Link Commander, `loadfile build/output/demo.elf`, `r` and `g` download and start the firmware. OpenOCD uses the SoC and probe configurations in `boards/openocd/` of the SDK together with `hpm5301evklite.cfg` in the board directory, as described at the top of these files. At run time the LED blinks with a 250 ms cycle.

## 6. 修改引脚与时钟 / Changing Pins and Clocks

引脚和时钟由 HPM Pinmux Tool 工程 `boards/hpm5301evklite/tool_config.hpmpc` 描述，`pinmux.c/h` 和 `clock.c/h` 是该工程导出的代码。BSP 的引脚都在 `init_bsp_pins()` 中；`board.c` 用 `init_board_clock()`、`init_board_clock_source()` 和 `init_uart0_clock()` 设置系统时钟和控制台，其余外设时钟由 `User/main.cpp` 逐个调用对应的 `init_*_clock()`。修改时在 [tools.hpmicro.com](https://tools.hpmicro.com/) 的 Pinmux Tool 中导入该工程，修改后导出工程文件和代码，用它们替换 `boards/hpm5301evklite/` 中的 `tool_config.hpmpc`、`pinmux.c/h` 和 `clock.c/h`，再重新构建；新增外设时钟函数时，同时在 `User/main.cpp` 中调用它。工程文件由工具校验，在工具之外编辑过的工程文件无法再导入。

The pins and clocks are described by the HPM Pinmux Tool project `boards/hpm5301evklite/tool_config.hpmpc`; `pinmux.c/h` and `clock.c/h` are the code exported from it. The pins of the BSP are all in `init_bsp_pins()`. `board.c` sets up the system clocks and the console with `init_board_clock()`, `init_board_clock_source()` and `init_uart0_clock()`, and `User/main.cpp` calls the `init_*_clock()` function of each other peripheral. To change them, import the project into the Pinmux Tool at [tools.hpmicro.com](https://tools.hpmicro.com/), make the change, export the project file and the code, replace `tool_config.hpmpc`, `pinmux.c/h` and `clock.c/h` in `boards/hpm5301evklite/` with them, and build again; a new peripheral clock function is also called from `User/main.cpp`. The tool validates the project file; a project file edited outside the tool can no longer be imported.
